ICS Maker / Erinnerungen und Alarme

Erinnerungen in einer .ics-Datei

Legen Sie eine oder mehrere Erinnerungen für das Ereignis fest, und die Datei führt sie mit. Jede ist ein kleiner Block, den der Kalender liest und selbst einplant.

Titel, Ort, Datum und Uhrzeit, Zeitzone, Wiederholung, Eingeladene, Erinnerungen und Notizen — laden Sie dann die .ics-Datei herunter oder öffnen Sie sie direkt in Ihrem Kalender. Sie können auch einen Terminplan einfügen oder ein Dokument oder Foto anhängen, um mehrere Termine auf einmal zu erstellen.

Wie füge ich einem .ics-Ereignis eine Erinnerung oder einen Alarm hinzu?

Eine Erinnerung ist ein VALARM-Block innerhalb des Ereignisses: ACTION:DISPLAY für eine Benachrichtigung auf dem Bildschirm und TRIGGER:-PT30M für den Versatz, wobei PT eine ISO-8601-Dauer einleitet und das vorangestellte Minus dafür sorgt, dass sie vor statt nach dem Beginn ausgelöst wird. ICS Maker bietet Erinnerungen über das Formular an und schreibt pro Erinnerung ein VALARM, wobei der Versatz stets in Minuten angegeben wird – ein Tag vorher ist -PT1440M. Ein Ereignis kann hier bis zu zehn Alarme tragen, doch ob sie alle ankommen, entscheidet der lesende Kalender: Manche fügen daneben ihre eigene Standardeinstellung hinzu, und manche entfernen Alarme aus importierten Ereignissen vollständig, sodass eine heruntergeladene Datei auf einem Gerät keine Benachrichtigungen einplanen kann.

Der geschriebene Block

BEGIN:VALARM
ACTION:DISPLAY
DESCRIPTION:Reminder
TRIGGER:-PT30M
END:VALARM

Ein VALARM befindet sich innerhalb des Ereignisses statt daneben, sodass er damit mitreist. ACTION:DISPLAY ist eine Benachrichtigung auf dem Bildschirm – diejenige, die jeder Kalender unterstützt. Die Alternativen, AUDIO und EMAIL, sind weit weniger portabel: EMAIL bittet den lesenden Kalender insbesondere darum, eine E-Mail zu senden, was die meisten schlicht ablehnen.

Den Trigger lesen

TRIGGER:-PT30M ist eine Dauer, keine Uhrzeit, und das Minuszeichen bewirkt, dass sie vor dem Ereignis liegt – ein positiver Wert löst nach dem Beginn aus, was gelegentlich für eine Nachbereitung gewünscht ist. Die Buchstaben bilden eine ISO-8601-Dauer: PT leitet eine Uhrzeit ein, sodass PT30M dreißig Minuten, PT2H zwei Stunden und P1D einen Tag bedeutet. Dieser Builder gibt den Versatz stets in Minuten an – ein Tag vorher ist -PT1440M statt -P1D, was dieselbe Dauer ist und geringfügig unwahrscheinlicher auf einen anspruchsvollen Parser trifft.

Ein Trigger kann auch an das Ende gebunden werden (TRIGGER;RELATED=END:-PT15M, eine Viertelstunde bevor das Meeting enden soll) oder statt eines Versatzes einen absoluten Zeitpunkt erhalten. Beides sind manuelle Änderungen an der heruntergeladenen Datei; das Formular bietet Versätze ab dem Beginn an, was fast jeder Erinnerung entspricht.

Mehrere Alarme, und ob sie erhalten bleiben

Ein Ereignis kann so viele Alarme tragen, wie Sie möchten – eine Woche im Voraus zur Vorbereitung, eine Stunde im Voraus für die Anreise, fünf Minuten im Voraus für den Beitritt zum Anruf – und jeder ist ein eigener Block. Ob sie alle ankommen, entscheidet der Kalender, der die Datei öffnet: Eine Erinnerung ist Teil des Ereignisses, aber ein Kalender mit eigenen Standardbenachrichtigungen fügt möglicherweise eine eigene daneben hinzu, und manche entfernen Alarme aus importierten Ereignissen vollständig, statt eine Datei Benachrichtigungen auf Ihrem Telefon einplanen zu lassen. Prüfen Sie das erste Ereignis nach einem Import, bevor Sie einer ganzen Reihe davon vertrauen.

Fragen

Wie stelle ich eine Erinnerung 15 Minuten vor einem Ereignis ein?
Wählen Sie sie vor dem Herunterladen aus der Alarmliste aus, und die Datei erhält ein VALARM, dessen Trigger -PT15M lautet. Das Minuszeichen bedeutet vor dem Beginn; der Kalender, der die Datei öffnet, plant die Benachrichtigung selbst ein.
Kann ein Ereignis mehr als eine Erinnerung haben?
Ja. RFC 5545 setzt keine Grenze für die Anzahl der VALARM-Blöcke innerhalb eines Ereignisses, und das Hinzufügen einer zweiten Erinnerung hier schreibt einen zweiten Block; zehn ist die von diesem Builder erzwungene Obergrenze. Ein Paar aus einem Tag vorher und zehn Minuten vorher ist die übliche Kombination.
Warum ist meine Erinnerung nach dem Import der Datei nicht erschienen?
Der lesende Kalender entscheidet. Manche wenden auf alles Importierte ihre eigene Standardbenachrichtigung an, manche behalten die Alarme der Datei bei, und manche ignorieren importierte Alarme grundsätzlich, sodass eine heruntergeladene Datei keine Benachrichtigungen auf Ihrem Gerät einplanen kann. Öffnen Sie das Ereignis nach dem Import und prüfen Sie das Alarmfeld, bevor Sie die Datei an jemand anderen senden.
Was bedeutet TRIGGER:-PT1H?
Eine Stunde vor Beginn des Ereignisses. PT leitet in ISO 8601 eine Uhrzeit-Dauer ein, 1H bedeutet eine Stunde, und das vorangestellte Minus lässt den Versatz rückwärts vom Beginn laufen. Ohne das Minus würde sie eine Stunde nach Beginn des Ereignisses auslösen.
